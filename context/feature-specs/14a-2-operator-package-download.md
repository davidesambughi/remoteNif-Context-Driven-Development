# 14a-2 — Operator Package Download (ZIP + Cover Sheet)

<!-- Read before starting: AGENTS.md, progress-tracker.md, user-flows.md (Flow 8c), architecture-context.md, tech-spec.md -->

Wire the "Download package" button by implementing a streaming ZIP API route that bundles a generated cover-sheet PDF and all three customer documents into a single download for the operator to submit to ebalcão.

---

## Constraints

### Tokens

No web UI work in this unit — the only change to existing UI is wiring a button that already exists in 14a-1.

**Note on `@react-pdf/renderer` styling:** the cover sheet PDF uses `@react-pdf/renderer`'s own `StyleSheet.create()` API, which is the correct and required way to style PDF components. This is NOT the same as web inline styles — do not apply the "no inline styles" web rule here. The constraint against hardcoded values still applies: use named constants in the StyleSheet (e.g. `COLORS.heading`, font size numbers) rather than magic values scattered through the JSX.

### Architecture

- **API route** (not a Server Action) — `app/api/operator/package/[orderId]/route.ts`. This must be an API route because it returns a binary streaming response (`application/zip`), not a JSON result. Server Actions cannot return binary streams.
- Business logic extracted to `lib/operator/packageBuilder.ts` — the route handler itself is thin (auth → fetch → build → stream).
- DB query for package data: `getOperatorPackageData(orderId, operatorId)` added to `lib/db/queries.ts`. Fetches the order, personal details, and the 3 active document records (file paths only) in one query.
- File retrieval: use the Supabase **admin client** (`lib/supabase/admin.ts`) to download documents from Supabase Storage — operator does not own these files, so the service-role client bypasses RLS.
- Cover sheet PDF: reuse `@react-pdf/renderer` (already installed from Feature 09b). New template file at `lib/operator/CoverSheet.tsx`.
- ZIP creation: `jszip` — generate the ZIP fully in memory using `zip.generateAsync({ type: 'nodebuffer' })` and return the resulting `Buffer` directly in the `Response`. Do not use `generateNodeStream()` or pipe to a `ReadableStream` — in-memory generation is correct and sufficient for the small payloads in this flow (see Scope Limits).
- No files are persisted to Supabase Storage as part of this flow — generate, stream, done.

### TypeScript

- Strict mode. No `any`. No type assertions without a comment.
- The route handler returns `Response` with correct headers — type it explicitly.
- `getOperatorPackageData` return type must be explicitly defined as an interface in `lib/db/queries.ts`.

### Validation

```typescript
// app/api/operator/package/[orderId]/route.ts
// Validate the route param at the top of the handler
const ParamsSchema = z.object({
  orderId: z.string().uuid(),
})
// Derive the typed result — do not redeclare orderId: string manually
type Params = z.infer<typeof ParamsSchema>
```

No form input — the only input is the `orderId` path parameter. Use `ParamsSchema.parse(params)` and destructure the typed result; do not cast or redeclare the type.

### i18n

No new user-facing strings. The button label ("Download package") was added in 14a-1. The API route returns binary content, not UI text.

## Implementation

1. **Add `getOperatorPackageData()` to `lib/db/queries.ts`.**

   - Return type:
     ```typescript
     export interface OperatorPackageData {
       order: {
         id: string
         tier: string
         fullName: string
         dateOfBirth: Date
         nationality: string
         passportNumber: string
         passportExpiry: Date
         address: string
       }
       documents: Array<{
         type: 'passport' | 'proof_of_address' | 'signed_poa'
         filePath: string
         mimeType: string
       }>
     }
     ```
   - Query: join `orders` and `documents` where `documents.supersededAt IS NULL` (active records only) and `orders.status = 'documents_approved'`.
   - Returns `null` if the order does not exist, is not in `documents_approved` status, or does not have exactly 3 active approved documents.
   - The caller treats `null` as a 404.

2. **Create `lib/operator/CoverSheet.tsx`.**

   - React component using `@react-pdf/renderer` (`Document`, `Page`, `View`, `Text` from `@react-pdf/renderer`).
   - Props: derive from `OperatorPackageData` — do NOT redefine the shape:
     ```typescript
     import type { OperatorPackageData } from '@/lib/db/queries'

     interface CoverSheetProps {
       order: OperatorPackageData['order']
     }
     ```
   - **Nationality conversion:** the DB stores an ISO alpha-2 code (e.g. `'US'`). The cover sheet must display the full country name. Move the `resolveCountry(code: string): string` helper from `lib/pdf/poa-template.tsx` into `lib/utils/countries.ts` (exported alongside `COUNTRIES`) so both PDF templates share it. Import from there — do not write a third resolver.
   - Renders a clean, print-ready PDF — see Design section for layout.
   - Utility function `renderCoverSheetPdf(order): Promise<Buffer>` exported from this file. Uses `renderToBuffer` from `@react-pdf/renderer`.

3. **Create `lib/operator/packageBuilder.ts`.**

   - Exported function:
     ```typescript
     export async function buildOperatorPackage(
       data: OperatorPackageData,
       supabaseAdmin: SupabaseClient
     ): Promise<{ zipBuffer: Buffer; fileName: string }>
     ```
   - Steps:
     a. Generate cover sheet PDF buffer via `renderCoverSheetPdf(data.order)`.
     b. For each of the 3 documents: download the file from Supabase Storage using `supabaseAdmin.storage.from('documents').download(filePath)`. Convert the returned `Blob` to a `Buffer`.
     c. Determine file extension from `mimeType`:
        - `application/pdf` → `.pdf`
        - `image/jpeg` → `.jpg`
        - `image/png` → `.png`
     d. Create a `JSZip` instance. Add all 4 files into a folder named `nif-application-${data.order.id}/`.
     e. Generate ZIP as a `Buffer` using `zip.generateAsync({ type: 'nodebuffer' })`.
     f. Return `{ zipBuffer, fileName: `nif-application-${data.order.id}.zip` }`.

4. **Create `app/api/operator/package/[orderId]/route.ts`.**

   - `GET` handler only.
   - Steps:
     a. Validate `params.orderId` with `ParamsSchema` — return 400 if invalid.
     b. Auth: get current user with the server Supabase client → `requireRole('operator')` equivalent inline check (check `users.role === 'operator'`). Return 401 if not authenticated, 403 if wrong role.
     c. Call `getOperatorPackageData(orderId)` — return 404 if null.
     d. Call `buildOperatorPackage(data, supabaseAdminClient)`.
     e. Return:
        ```typescript
        return new Response(zipBuffer, {
          status: 200,
          headers: {
            'Content-Type': 'application/zip',
            'Content-Disposition': `attachment; filename="${fileName}"`,
            'Content-Length': String(zipBuffer.byteLength),
          },
        })
        ```
   - Wrap in try/catch — return 500 with a plain text error message on failure (not JSON — binary route).

5. **Verify the `QueueRow` `<a>` button from 14a-1 works end-to-end.**

   - The button was rendered in 14a-1 as `<a href="/api/operator/package/${item.id}" download>`. No code changes needed here — just confirm the link resolves correctly now that the route exists.

## Scope Limits

- Do NOT add progress indicators or streaming chunk-by-chunk download — generate the full ZIP in memory and return it. The packages are small (3 documents + 1 PDF).
- Do NOT persist the generated ZIP to Supabase Storage — generate once, stream, discard.
- Do NOT send any emails from this route.
- Do NOT add a download log or audit entry for package downloads — operators are trusted; logging submission (not download) is sufficient (handled in 14a-1's `markOrderAsSubmitted`).
- Do NOT modify the cover sheet design based on locale — this is an internal operational document, English only.
- Do NOT handle the case where documents are missing gracefully in the UI — `getOperatorPackageData` returns null if all 3 approved documents are not present, and the route returns 404. The admin panel is responsible for preventing this state from occurring.

## Check When Done

- `GET /api/operator/package/{validOrderId}` returns a `200` response with `Content-Type: application/zip` when called by an authenticated operator.
- The downloaded ZIP contains exactly 4 files: `cover-sheet.pdf` + 3 document files with correct extensions.
- `cover-sheet.pdf` includes the customer's full name, date of birth, **full country name** (not ISO code), passport number, passport expiry, address, tier, and order ID.
- `GET /api/operator/package/{orderId}` returns `401` for unauthenticated requests.
- `GET /api/operator/package/{orderId}` returns `403` for non-operator users.
- `GET /api/operator/package/{orderId}` returns `404` for an order not in `documents_approved` status.
- `GET /api/operator/package/{invalidUuid}` returns `400`.
- Clicking "Download package" in the operator queue triggers a file download in the browser.
- `npm run build` passes.
- `npm test` passes (unit tests for `renderCoverSheetPdf`, `buildOperatorPackage`, `getOperatorPackageData`, and the API route 400/401/403/404 paths are deferred to spec **14a-2-T**; this unit's acceptance is manual verification of the items above).
